# Arca 桌面 GUI

以目标用户当前打开的窗口为准。操作前核对正式安装版与开发预览，`设置 → 检查更新` 行旁显示当前版本，macOS 正式版的标准位置是 `/Applications/Arca.app`。英文界面依功能和角色匹配，示例中的中文标签对应 4.0.2。

## 找到工作区

| 界面位置 | 用途 | 详细手册 |
| --- | --- | --- |
| 顶栏 **Models** | Provider、Model Profile、凭据存储、模型试验台 | [连接、模型与试验台](workflows/models.md) |
| 顶栏 **MCPs** | 查看中央目录、来源和同身份副本，新增或编辑服务 | [MCP 库与来源](workflows/mcp.md) |
| 顶栏 **Skills** | 浏览来源，导入中央 Skill，查看实际副本和使用方 | [Skills 生命周期](workflows/skills.md) |
| 顶栏 **Agents / Subagents / Hooks** | 对应的中央定义库。Agents 在这里是启动用定义 | [Agent 原生资源](workflows/agents.md#管理原生资源) |
| **选择 Agent**、置顶图标 | 进入具体客户端工作区，macOS 可用 ⌘K 打开选择器 | [识别客户端](workflows/agents.md#识别客户端) |
| 右上 **设置** | 默认终端、编辑器、外观、语言、代理、日志、重新扫描与更新 | [安装与设置](workflows/settings.md) |
| **Trace**、Agent 页 **抓包** | 已有本地会话与网络诊断 | [诊断手册](workflows/diagnostics.md) |

狭窄窗口会折叠图标和文字。资源导航项、设置与选择器可通过可访问性名称或提示识别。左栏通常是 Provider 或来源筛选，主区是该范围的搜索结果、详情和新增入口。没找到资源时先查筛选和搜索。

## 用中央库创建，再到 Agent 使用

1. 按任务打开相应中央库。从列表和详情核对准确对象，使用中央库的新增、导入或编辑入口。
2. 通过 **选择 Agent** 或置顶入口进入目标。查看 CLI、Desktop、IDE 或 Plugin 标识，同名时以身份和能力校验目标。
3. 在 **MCPs / Models / Skills** 标签用 **添加** 选择已有中央资产。验证新增关系、启停、当前模型及传输。需要改变现存关系时，先打开该关系的菜单。
4. 查看通知和该关系的状态。共享配置文件、多个 Skill 目录或外部修改会增加实际影响范围。通过详情和当前可用动作定位到具体目标。[同步与恢复](workflows/recovery.md)

Provider 编辑、MCP 目录编辑和中央 Skill 更新可以影响多个消费者。按用户任务先看详情中列出的使用方。关闭确认框前区分编辑、停用、解除使用和删除中央资产。

## 常用操作定位

| 要做什么 | 在窗口中找什么 |
| --- | --- |
| 新建带 Key 的 Provider | **Models → 添加 Provider**。核对模板、Base URL、模型列表 URL、协议和 Endpoint Path。通过凭据控件输入 Key |
| 对比不同模型响应 | **Models → 模型试验台**，在浏览器页核对运行设置和请求预览，再按授权发送 |
| 新增一个 HTTP MCP | **MCPs → 添加 MCPs → 手动配置**，核对类型和 URL。粘贴配置及远程订阅各有单独入口 |
| 只导入一个 Skill | **Skills → 添加**，选择该 Skill 的目录或目录 URL。当前桌面导入提交来源后会处理其全部候选 |
| 给特定 Agent 选模型 | **选择 Agent → 目标 → Models**。区分添加、启用和设当前。若客户端仅支持会话内选择，在目标会话验证 |
| 更换工作目录或终端启动 Agent | Agent 页启动区和 **编辑配置**。桌面应用通过系统启动，CLI 可选择目录和终端 |
| 查看实际文件位置 | Agent 页能力内的 **配置**，或资产/关系详情。看清文件、目录、是否共享与可编辑能力 |
| 核对已经安装的正式版 | **设置 → 检查更新** 旁的版本、应用包信息和目标窗口。若刚更新也检查资源列表是否正常 |

## 做桌面操作时怎样留证据

- 通过当前桌面工具定位对的 App、窗口和控件。优先用可访问性角色、名称、选中状态与列表范围；必要时用截图判断弹层、导航位置和视觉状态。提交前先确认当前焦点、字段和目标。
- 点击后重新观察界面。等通知、加载或结果弹窗完成，再打开目标列表或详情确认变化。完成 Agent 启动以后，确认目标窗口、终端或浏览器实际打开。
- 优先使用界面已经提供的脱敏显示。涉及密钥输入、系统权限、用户草稿等需要人工处理时，沿当前环境的交接规则操作。
- 预置配置与实际窗口不一致时，先核对本地安装实例和数据根，再检查足够小的 CLI 状态范围。GUI 走到只读能力或官方引导时，按产品提供的路径推进。
- 操作遇到具体阻碍时记录当前页面、控件和已观察到的错误。按环境交接规则协作，控制权返回后重新观察目标结果。[诊断手册](workflows/diagnostics.md)
