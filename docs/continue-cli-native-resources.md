# Continue CLI: passive runtime identity and native resource boundaries

Continue CLI is the official npm package `@continuedev/cli`, command `cn`. This change supplies its version from verified public package metadata. It adds no native plugin host or plugin inventory. The actual catalog ID is `continue-cli`; passive dispatch must return `Some(continue_cli::runtime_version(selected))` for that ID even without a plugin host. An unknown package must therefore remain `Some(None)`, preventing an active `--version` fallback.

`data/native-runtime-continue-cli.json` is the runtime identity source of truth. Its strict `deny_unknown_fields` contract binds package name, version, ESM type, `bin.cn`, wrapper import/export and whole-member SHA-256 for `package.json`, `dist/cn.js` and `dist/index.js`. The selected command is resolved to its physical entry; only that package is considered. The exact wrapper imports `./index.js` and awaits `runCli()`. All three public files must match before the manifest's version is returned.

The reader uses its own finite `ScanBudget`, at most three guards and 16 MiB of aggregate identity bytes. JSON is capped at 64 KiB, the wrapper at 1 KiB. Whole bundle hashing streams rather than importing JavaScript. No-follow confined opens reject symlinked or special public members. Open descriptors and path metadata remain bound through final CAS, including device, inode and ctime on Unix; the selected alias and physical entry are rechecked. Missing, changed, unsupported, oversized or ambiguous identity returns `None`.

The version probe itself is not a passive metadata operation. In the published source, `src/index.ts:24` imports `getVersion`; `src/version.ts:65` invokes `getLatestVersion()` at module scope. That path obtains `node_machine_id.machineIdSync()` at lines 22–24, then fetches `https://api.continue.dev/cn/info?id=...` at lines 40–43. These are static call/import facts, not observations of target execution. This investigation did not run `cn`, `--help`, `--version`, login, hooks, MCPs, helpers or native addons.

The tarball's SRI and SHA-1 were independently checked. Its 454 extracted members match the isolated installed package byte for byte. ECDSA signatures and provenance attestations were retained as registry metadata but were not independently verified. Installation used the existing npm/Node runtime, isolated npmrc/cache/prefix and disabled lifecycle scripts. A non-overwriting user-level `cn` symlink makes the installed wrapper discoverable on PATH. Platform optional prebuilt dependencies were added with `--ignore-scripts --include=optional`; their official SRI and installed member digests are retained in private acquisition receipts. No shell startup file, service, credential or global runtime was changed.

The published package contains application sources, an esbuild metafile and a source map. The source map exactly matches the shipped resource-loader source bodies; its generated positions bind those sources to the real bundle. REA parent Evidence `ev_20640fc80818adf7cf0de1ecaf22c0bb7a9806ebfbddaf58b33cec1aa4385c78` and entry Evidence `ev_27f9b9ac3edb7cb71e6d50beeabe8e037f223df6c94ee10e51054c05934b3b7d` bind root fingerprint `dd9ed3244ce0cf0cc7a554b80dca5d39110c002fb73b1fd9b23b3431c34aa84e`. Three complete Evidence records were exported, parsed and hashed locally; the owned REA session was closed. Static parsing covered 434 JS/TS files with zero parse failures, but semantic coverage is partial because of the analyzer's resource budget. Full limitations remain in the retained bundle.

The native resource mechanisms are separate:

- **Skills:** `src/util/loadMarkdownSkills.ts:61–146` scans one level under cwd `.continue/skills`, cwd `.claude/skills` and global Continue `skills`. Each `SKILL.md` requires nonempty frontmatter name and description. Child directory symlinks are not accepted by `Dirent.isDirectory()`. The asynchronous push order means duplicate names have no guaranteed project/global precedence. Global `~/.claude/skills` and `.agents/skills` are not roots of this loader.
- **Rules and commands:** `src/systemMessage.ts:89–151` scans cwd/global Continue rules recursively; inline configuration rules are also supported. `src/slashCommands.ts:296–350` resolves built-ins, assistant prompts, invokable rules and Skills in that order. These are not a plugin command registry.
- **Hooks:** `src/hooks/hookConfig.ts:73–123` reads global Claude, global Continue, project Claude, project Continue, project-local Claude and project-local Continue settings in that order. Matcher groups append and all sources can run; any truthy `disableAllHooks` remains true. The `HookSettingsFile.description` comment saying “Plugin-level” is not a plugin manifest/loader.
- **MCP:** `src/services/MCPService.ts:61–102` connects resolved `assistant.mcpServers`; `ConfigService.processMcpServers` adds CLI/agent blocks. MCP transport compatibility does not establish native plugin format compatibility.
- **Configuration and registry:** `src/env.ts:6–11` runs dotenv initialization and uses `CONTINUE_GLOBAL_DIR || ~/.continue`. Actual `determineConfigSource` at `src/configLoader.ts:84–100` chooses explicit `--config`, global `config.yaml`, then remote default config. The [pinned configuration documentation](https://github.com/continuedev/continue/blob/d3f60ba9dd3fb5bfd3c91d6fbb41ce1aa768db45/docs/cli/configuration.mdx) and comment also mention saved URI precedence, but this release's decision function does not read it. Config `uses/with/override` blocks are composition; the bundled `RegistryClient` reads file blocks and rejects slug package resolution. Legacy `hubLoader` exports throw rather than installing packages.

The image optional-dependency boundary was also checked statically. `src/ui/hooks/useChat.imageProcessing.ts:6–14` constructs a lazy `import("sharp")` only when `processImageWithSharp` is invoked for an image placeholder (lines 20–54, 109–121). Failure returns the original buffer and `isJpeg: false`; MIME detection preserves the original format and buffers larger than 10 MiB are skipped. No Sharp import or native binding is initialized by module import. Installing official platform prebuilt packages does not by itself prove the optional JavaScript `sharp` wrapper is resolvable, or that image processing works at runtime.

The complete entry/loader/schema review and bounded search of 350 operational application/config-yaml source files did not establish an independent native plugin manifest, install registry or extension loader in this release. No claim of Agent Plugins v1 support follows from MCP, Skills or Claude-compatible hooks. Other releases, IDE extensions, alternative distributions, account-specific remote behavior and actual enabled resources remain unknown.

Fifteen `TestHome`-isolated regression sources were written before their corresponding implementation. They cover manifest identity, real wrapper shape, full-bundle changes, unsafe paths, finite budgets, symlink/FIFO rejection, alias retargeting, member CAS, the no-execution fallback and discovery of the official `cn` launcher independently of the Continue IDE host. Under the explicit fast-mode instruction, tests, validators, formatting and target startup were not run. Production compilation and development-preview acceptance are recorded separately by the delivery owner.
