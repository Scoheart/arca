# MUX 运行内存审计与本地优化

## 范围与测量口径

用户目标：拉取最新代码，深度分析并优化 MUX 运行时内存。已快进合入 8 个远端提交，基线为 `9b89ec1` / 1.14.4。两轮优化先在本地完成验证，随后用户授权发布；版本提交与正式产物由 Direct Stable 生成，开发预览不替代正式产物验收。

macOS 的 RSS 不包含全部已压缩内存，不能单凭它判断应用占用。首先分别测量 Rust 主进程、WebContent、GPU、Networking，使用 `footprint` 的物理占用；抓包引擎的大正文试验另采样进程组的峰值 RSS，不把两种指标混加。所有数值使用 MiB。

旧开发预览的 WebContent 曾占约 2.19 GiB，其中约 2.1 GiB 已压缩，RSS 却只有约 152 MiB。该进程随旧预览退出。这个长期运行的开发进程不能作为新版本性能收益的对照，也不能据此断言 HMR 或某个页面单独造成泄漏。

对照使用同一份最新源码的改动前后构建、同一机器、相同窗口和真实 HOME 数据；前端嵌入生产构建，排除 HMR 累积差异。Trace 样本是本机合成文件：8 条约 1.6 MiB / 50000 行的正文，连续查看前 6 条；不包含用户会话或真实凭据。Core 索引试验隔离 HOME/MUX_HOME，使用 5 个会话、每个 1000 条约 5 KiB URL 的摘要。不是全场景统计基准。

## 实测结果

| 场景 / 指标 | 改动前 | 改动后 | 变化 |
|---|---:|---:|---:|
| 冷启动 WebContent 物理占用 | 96.1 | 94.9 | 基本相同 |
| 查看一条大 Trace：WebContent | 290.1 | 143.2 | -50.6% |
| 连续六条大 Trace：WebContent | 358.0 | 197.5 | -44.8% |
| 六条大 Trace：四个进程 Footprint 合计 | 644.6 | 501.3 | -22.2% |
| 多会话索引：独立 Core 探针 Footprint | 30.9 | 19.0 | -38.3% |
| 32 MiB 上传及下载：抓包引擎峰值 RSS | 131.2 | 100.7 | -23.3% |

六条 Trace 场景中 GPU 从 237.0 到 235.8 MiB，未显示明显改善；Rust 主进程从 43.1 到 60.9 MiB，不能宣称这里也下降了。收益主要来自 WebContent。进程缓存和分配器回收有延迟，不以关掉应用、缩小窗口或忽略 GPU 来宣称优化。

## 已修改的热点

1. **大正文排版。** Trace 和 Capture 不再把数万行或数 MiB 文本整块放进 `<pre>`。共用 `BoundedText`，每段最多约 32 Ki 个 UTF-16 单元 / 800 个换行，只缓存分段偏移；不切断代理对。正文仍完整保留，可逐段查看，复制及 Core 导出保留全文。切换记录/格式重置段号，流式更新保留当前段并处理内容缩短。导航支持中英文。
2. **Trace 隐藏序列化和详情缓存。** 完整正文页不预先序列化隐藏 JSON；关联返回的 JSON 只在相关页计算。六条详情缓存再加 4 MiB 估算预算，超大详情仅作为当前记录显示，不再缓存六份。切换来源、无会话和卸载时清理缓存，并继续用 generation 拒绝过期请求。
3. **Model/Provider 缓存。** 模型库为一份、4 MiB / 30 秒；Provider 发现列表为最多八份、合计 4 MiB / 5 分钟。统一按 LRU 与 TTL 释放；到期后即使没有再次访问也清除。超预算数据仍正常返回调用者，只不长期缓存。保留同请求复用、revision 校验和失败重试。Models 页面不再用永久 state 保留初始化时的旧模型库快照。
4. **Core 抓包索引。** 从最多四个历史会话改为两个，并增加 16 MiB 的摘要及节点开销预算。淘汰仅影响只读缓存；磁盘记录不删，旧游标通过 `reset` 补回完整列表。单次查询仍按原条数和文件读取边界校验，预算不是整个进程的堆内存硬上限。
5. **JSON/Gemini Trace 读取。** `document_items` 改为惰性迭代，移动已经生成的记录，避免再克隆整份规范化正文。分页只保留当前页的小摘要，详情只保留选中记录及其配对结果。先学习完整文档的脱敏上下文，再截取摘要；不以提前截断或减少上下文来节省内存。
6. **抓包引擎的大正文。** 第一轮覆盖已声明 Content-Length 且超过录制上限的请求和普通响应，第二轮再覆盖未知长度，见下文。记录明确标注正文未保存，并累计实际转发字节；不改网络字节。SSE 保持原有事件解码与脱敏流程，WebSocket 的帧记录流程保持原边界。官方流式行为见 [mitmproxy Streaming](https://docs.mitmproxy.org/stable/overview/features/#streaming)。

## 深度复核的其他边界

- 资产列表属于用户正在查看的必要数据，不通过清空中央库、减少扫描范围或禁用观察来省内存。
- 观察队列有 256 条上限，事件域会合并，溢出时仍完整收敛；没有引入后台扫描或新的常驻进程。
- runtime-version 缓存有数量和时间边界；models.dev 的内存请求缓存已有 TTL；国际化 DOM 状态用 WeakMap，观察器卸载时断开。没有证据将它们判定为本次主因。
- 事务草稿可能包含待提交凭据和活跃计划租约，必须沿 commit/cancel 生命周期清理；不拿普通展示缓存的任意 TTL 去失效仍由用户持有的操作。
- 已加载 Trace 摘要和 Capture 请求树仍按当前窗口保留；超大集合的列表虚拟化可继续优化，但本次未用删记录或限制历史访问代替内存治理。
- 未知长度普通 HTTP 正文的缓冲边界已在第二轮补齐；并发连接、平台图形缓存和整个 WebKit 分配器仍不受这些单项预算直接限制。本次不声称任意流量下都存在一个整个应用的固定内存上限。

## 第二轮：未知长度正文与导出峰值

用户继续要求内存优化。本轮对照为第一轮本地实现与本轮最终实现，不混用原 Git 基线；测量构建均为 1.14.4，本地验收完成后再按用户授权交付。

| 独立受控场景 / 峰值 RSS（MiB） | 第一轮 | 第二轮 | 变化 |
|---|---:|---:|---:|
| Core 导出 32 条请求、64 MiB 正文 | 200.8 | 13.2 | -93.4% |
| 引擎：32 MiB 分块上传/下载及关闭连接定界下载 | 236.5 | 106.3 | -55.0% |

导出测量只包含独立 Core 探针；引擎测量只包含 mitmdump 及其后代进程，两者不是整个 MUX 的内存。引擎对照使用相同的两种大正文案例；另一次包含九项的最终兼容性试验单独记录，不用额外案例替代相同负载对照。单机单次测量存在波动，原生 GPU 与大列表问题仍不能据此宣称解决。

实现：

- **导出逐条编码。** 不再同时构造全部 `CapturedFlow`、整个 `serde_json::Value` 和完整 JSON 字节数组。序列化器每次读取一条安全详情，写入有缓冲的私有临时文件；完整编码、flush、sync 成功后，复用 `safe_write` 现有的 `publish_path_noreplace`，以不覆盖方式生成目标。保留会话字段、全部正文、记录顺序、单条导出及 0600 权限。错误时只清理本次临时文件，已有文件和符号链接不被覆盖。
- **未知长度正文有界录制。** chunked 和关闭连接定界的普通 HTTP 正文改用流式转发回调。已知小正文仍走原路径，已知超限正文直接省略；未知长度最多保留 2 MiB 解码内容，超限立即释放。gzip/deflate 增量解压有输出上限；转发字节和字节计数保留，超限、异常压缩及无法安全解析的正文明确省略。未完整接收的正文不写入，避免尚未建立完整脱敏上下文时泄露回显凭据。空请求不会误标为截断。
- **转发对象的生命周期。** 有界正文状态挂在受支持的 `message.stream` 回调中，不往原生 Flow metadata 塞无法序列化的自定义对象。结束时移除回调持有的录制缓冲。SSE 与 WebSocket 仍走原有专用录制路径，101 升级响应不进入普通正文收集器。
- **Capture 按需派生展示。** Overview/Timing 不再生成隐藏的 Pretty 正文；Headers/Query 也不生成另一份正文字符串。只在 Structure 模式构造请求树，Sequence 释放该树。列表 URL 不预先展开每条请求的 query 参数；只有选中 Query 时才展开，复制和导出仍保留原内容。

最终证据：

- 两次导出 JSON 的解析结果逐字段相同，32 条记录及 64 MiB 正文完整；单条导出相同。已有目标、符号链接、损坏记录和临时文件清理验证通过。
- 官方 mitmdump 的隔离显式 HTTP 代理通过未知长度大上传/下载、关闭连接定界、小 JSON、gzip、deflate、压缩膨胀、损坏压缩、二进制、SSE；上传/下载 SHA-256 与字节数正确，fixture 凭据未进入录制文件。不是全部 Agent 的真实模型流量验收。
- 源码边界探针通过 2 MiB 与 2 MiB+1、部分正文省略、完整上下文脱敏、空正文、回调原样返回及完成后释放缓冲。
- 最终前端、CLI/Core、Tauri 编译通过；Python 语法与差异空白检查通过。未运行 cargo/npm 测试套件、fmt、clippy 或发布检查。
- 原生开发预览用真实 HOME 数据，检查 1200×820、900×600，Structure/Sequence 的树移除与恢复、Query 参数、正文及复制/导出操作入口。通过 `npm run tauri dev` 启动验证后，最终只保留一个已更新二进制的本地预览及 Vite，避免两份开发进程占用内存。正式安装版未替换。
- 第二轮复现资料在父仓忽略目录 `workspace/local/research/mux-memory-round2-2026-10-13/summary.json` 及相邻脚本、日志；实验引擎和作用域进程均收尾。
