# 共享网络上下文

本轮将已发布的代理修复改为跨客户端复用的 Core 能力。抓包与公共网络用例都不再通过 `agent_id == "pi"` 选择代理规则，用户端口由配置及运行上下文决定。

## 边界

- `core/network/context.rs` 定义来源接口、延迟求值、统一 URL 校验及带来源的解析结果。来源缺失才继续；读取或校验失败直接返回错误。调用方可提供自己的来源组合，不依赖 Agent 或抓包会话。
- 原生文件使用目录、目录环境变量、相对文件、格式、字段指针五项声明；同一读取器处理 JSON、TOML、YAML，并限制普通文件及读取大小。
- `core/network/platform.rs` 实现终端及系统来源，不访问抓包状态或目录。终端查询使用一次性私有临时目录，来源可返回 HTTP/SOCKS；认证信息不会写入交接文件。
- `application/network.rs` 装配 Agent 默认上下文并提供公共解析入口；`data/agent-network-sources.json` 登记已核验的原生来源。目前声明保留已有 Pi 用户配置映射，其他客户端共用环境、平台和显式出口机制；新增已核验文件映射只需声明数据。
- `capture/routing.rs` 将共享结果接入抓包传输。当前传输只接受 HTTP 上游，其他协议明确报错；共享网络层仍可为其他消费者解析 SOCKS。这是执行器能力边界，和 Agent 身份无关。

既有窗口生命周期已集中在 Tauri 原生窗口模块，关闭、隐藏、重新打开和退出均为应用级行为。本轮无需追加客户端或快捷键场景分支。

## 验证

使用临时调用程序直接执行实际 Core API，隔离 HOME/ARCA_HOME：Pi、Codex、OpenCode 的启动环境分别使用不同代理端口，公共网络入口与抓包适配入口均得到正确结果；这验证解析及适配，不代表实际启动了三个客户端。

另外验证 JSON/TOML/YAML 合成来源、原生配置声明、首个来源命中后不读取后续来源、无配置直连、首个来源损坏时报错、共享层解析 SOCKS 而抓包层拒绝不支持的传输。终端交接片段覆盖不同端口、IPv6、不同协议及含认证地址拒绝持久化。

真实 Pi 1.3.0 → 抓包代理 → 随机端口 HTTP 上游 → 本机 HTTPS 模型服务另行复核，上游地址由新公共网络入口解析。使用只能由上游映射的测试域名，保留 TLS 校验，核对 CONNECT、模型 OK 回复、200/complete 抓包记录和退出收尾。

Rust 编译与前端生产构建通过。按仓库默认没有运行 cargo/npm 测试套件；Linux 上的功能检查不替代 macOS 原生终端及快捷键实机交互验收。正式发布信息以 Git 历史和 Release 为准。
