# 抓包上游代理与 macOS 窗口关闭

用户补充：Pi 需要通过本机 6789 HTTP 代理访问模型，直连不可用。随机抓包入口不能替代这个上游；正确链路为 Pi → Arca 临时监听端口 → 用户 HTTP 代理 → 模型服务。

原自动出口只覆盖 Arca 代理、Arca 进程环境和系统代理。由 Finder 启动的 Arca 通常不会继承交互式终端的代理变量，且原实现忽略 Pi 的 `httpProxy` 与 Agent 启动环境，因此会错误选择直连。此前只通过本机模型端点验证的结果不覆盖必经上游场景。

修复后，Core 在覆盖 Agent 的抓包入口前解析上游，顺序为 Arca 代理、Agent 启动环境、Arca 进程环境、终端登录环境、Pi 用户设置、macOS 系统代理。终端环境先于 Pi `httpProxy`，对应 Pi 将该设置用于缺失的 HTTP/HTTPS 环境变量的行为；手动指定出口仍优先于自动解析。终端查询有超时，丢弃启动输出，只允许私有一次性文件携带无认证 HTTP 地址或固定标记，不导出完整环境，也不保留代理凭据。配置错误或不支持的代理不会切换直连。

前端在开始前显示自动解析的上游地址和来源，检测失败时提供明确错误；代理选择与临时抓包监听地址保持独立。只在另一个终端交互设置、未保存到启动配置的变量无法从 GUI 可靠继承，须手动指定出口。

双代理复现使用官方 Pi 1.3.0、mitmproxy 12.2.1 和监听 6789 的本机 HTTP CONNECT 代理。模型地址使用 `model.arca.invalid`，只有上游代理将其映射到本机 HTTPS 模型服务，不能靠直接 DNS/直连成功。保留客户端及上游 TLS 校验；观测到 6789 接收 CONNECT、Pi 返回 OK、抓包保存 200/complete。首次复现脚本漏设正式命令的 lazy connection 参数，产生了错误的提前直连判断；补齐实际启动参数后双代理链路通过，未据此修改原本正常的转发代码。

macOS 主窗口现在有显式 Close Window 原生菜单与 Cmd+W 快捷键。关闭请求只隐藏并保留主窗口，Dock Reopen 重新显示、取消最小化并聚焦。标准 Hide 与 Quit 继续由原生菜单处理，后台抓包仅在实际退出时收尾。macOS 菜单及 Terminal 的实机交互仍需原生环境验收，Linux 上的网络复现不替代它。
