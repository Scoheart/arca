# Provider Catalog sources

## AkashML — 2026-10-19

`akashml` is a gateway Provider for [AkashML](https://akashml.com/), managed inference for open models (GLM 5.3, Kimi K3, Qwen3.8 27B, Qwen3.6 35B A3B, GPT OSS 120B/20B, Llama 3.3 70B) running on the Akash Network, billed from pay-as-you-go credits with trial credits on signup. The [Introduction](https://akashml.com/docs/getting-started/introduction) states that the API is OpenAI-compatible at `api.akashml.com`, calls `POST https://api.akashml.com/v1/chat/completions` with `Authorization: Bearer YOUR_API_KEY`, configures the OpenAI SDK with `baseURL: "https://api.akashml.com/v1"`, and has users create keys under [Settings → API Keys](https://akashml.com/docs/platform/settings) in the [playground](https://playground.akashml.com/settings), so Arca uses that Base URL with Chat Completions as the default. The [Anthropic SDK reference](https://akashml.com/docs/api-reference/anthropic) and [Claude Code guide](https://akashml.com/docs/guides/claude-code) document an Anthropic Messages-compatible `POST https://api.akashml.com/anthropic/v1/messages` with the same Bearer key (keys prefixed `akml-`) and set `ANTHROPIC_BASE_URL` to `https://api.akashml.com/anthropic`, so Arca stores Anthropic Messages at that URL. On that endpoint model IDs alias `/` as `--` (for example `zai-org--GLM-5.3`); the OpenAI endpoints keep slashed IDs. No Responses or Gemini format is documented. Probes without a key: `POST /v1/chat/completions` and `GET /v1/models` return 401 `Missing authorization header` (a bogus key gets `Invalid or expired API key`), `POST /anthropic/v1/messages` returns 401 `authentication_error`, `GET /anthropic` returns 200 `{"status":"ok"}`, and `/v1/responses` returns 404.

Model discovery uses the OpenAI catalog decoder with a required credential: the [List models reference](https://akashml.com/docs/api-reference/models/get-v1-models) documents `GET /v1/models` with Bearer auth, returning an OpenAI-shaped `data` array (`id`, `name`, `context_length`, `max_output_length`, `input_modalities`, `pricing`), and the unauthenticated probe returns 401. No models are hard-coded because the catalog is live. Only `api.akashml.com` is mapped for host inference; `akashml.com`, `www.akashml.com`, and `playground.akashml.com` resolve to `custom`.

## Fikra API — 2026-10-18

`fikra` is a gateway Provider for [Fikra API](https://fikraapi.co.ke/), an OpenAI-compatible model gateway operated by Lacesse Ventures that is paid from a prepaid wallet via M-Pesa, other mobile money, or card. The [documentation](https://docs.fikraapi.co.ke/) lists the Base URL `https://api.fikraapi.co.ke/v1` with `Authorization: Bearer` keys prefixed `fk_live_`, generated from the [dashboard](https://fikraapi.co.ke/dashboard); the [Endpoints](https://docs.fikraapi.co.ke/endpoints) page documents only `POST https://api.fikraapi.co.ke/v1/chat/completions`, so Arca uses that Base URL with Chat Completions as the default and no additional endpoints. The [free model page](https://fikraapi.co.ke/models/fikra-free-deepseek) shows the same OpenAI SDK setup for `fikra-free-deepseek` ($0 input and output, running `deepseek-v4-flash-0731` with 1M context). Probes without a key: `POST /v1/chat/completions` returns 403 `Not authenticated` (a malformed key gets `Invalid API key format.`), while `POST /v1/responses` and `POST /v1/messages` return 405, so no Responses or Anthropic Messages endpoint is exposed and no Gemini format is documented.

Model discovery uses the OpenAI catalog decoder with an optional credential: the [Authentication](https://docs.fikraapi.co.ke/authentication) page calls `GET https://api.fikraapi.co.ke/v1/models` with the Bearer key, and the same request without a key returns HTTP 200 with an OpenAI-shaped `data` array (`id`, `name`, `pricing`, `context_window`, `max_output_tokens`), including `fikra-free-deepseek`, `fikra-pro-20b`, `fikra-auto`, and third-party models. No models are hard-coded because the catalog is live. Only `api.fikraapi.co.ke` is mapped for host inference; `fikraapi.co.ke`, `www.fikraapi.co.ke`, and `docs.fikraapi.co.ke` resolve to `custom`.

## SenseNova Token Plan — 2026-10-18

`sensenova` is an official Provider for SenseTime's SenseNova (商汤日日新) LLM API, sold as the [Token Plan](https://www.sensetime.com/en/news/sensenova-u1-5-lite-token-plan-20260911-1741). The [API docs](https://platform.sensenova.cn/docs) state that "all API requests are based on `https://token.sensenova.cn/v1`", call `POST /v1/chat/completions` with `Authorization: Bearer $SENSENOVA_API_KEY`, and have users create a key starting with `sk-` under [Console → API Keys](https://platform.sensenova.cn/console/keys), so Arca uses that Base URL with Chat Completions as the default. The same docs document an OpenAI Responses-compatible `POST https://token.sensenova.cn/v1/responses` (stateless only: no stored responses, `previous_response_id`, or non-function built-in tools) and an Anthropic Messages-compatible `POST https://token.sensenova.cn/v1/messages` that shares the same key and Bearer header; the Claude Code guide sets `ANTHROPIC_BASE_URL` to `https://token.sensenova.cn` without `/v1`. Arca therefore stores Responses at `https://token.sensenova.cn/v1` and Anthropic Messages at `https://token.sensenova.cn`. Unauthenticated probes of `/v1/chat/completions`, `/v1/responses`, `/v1/messages`, and `GET /v1/models` return HTTP 401 (`Authorization Not Found`, or `Forbidden` for a bogus key), while an unknown `/v1/` path returns 404.

Model discovery uses the OpenAI catalog decoder with a required credential: the docs' List Models section documents `GET https://token.sensenova.cn/v1/models` with the Bearer key, returning a `data` array whose entries carry `id`, `input_modalities`, `context_length`, and `max_output_length` (for example `sensenova-6.8-flash-lite`: text and image input, 262144 context, 65536 max output). The documented models are `sensenova-6.8-flash-lite` (chat, also on Responses and Messages), the image models `sensenova-u1.5-lite` and `sensenova-u1.5-fast` on `POST /v1/images/generations` and `/v1/images/edits`, and hosted third-party models (`deepseek-v4-flash`, `deepseek-flash`, `glm-5.2`, `kimi-k3`); none are hard-coded because the catalog is live. The console's Token Plan page describes a free public beta with a per-model quota of 1,500 calls every 5 hours, counted per model and shared across all keys on the account; this quota is not encoded. Only `token.sensenova.cn` is mapped for host inference; `sensenova.cn`, `www.sensenova.cn`, and `platform.sensenova.cn` resolve to `custom`.

## Bilibili Index-Translate — 2026-10-18

`bilibili-index-translate` is an official Provider for the free public API that Bilibili's Index team runs for its translation-specialized Index-Translate models (150 languages, image translation; [repository](https://github.com/bilibili/Index-Translate), [weights](https://huggingface.co/collections/IndexTeam/index-translate)). The README's [Free Online API](https://github.com/bilibili/Index-Translate#option-1-free-online-api-zero-gpu-setup) section calls `POST https://index-translate.bilibili.com/v1/chat/completions` (text and OpenAI `image_url` input) and `POST https://index-translate.bilibili.com/v1/responses` without any `Authorization` header, so Arca uses the Base URL `https://index-translate.bilibili.com/v1` with Chat Completions as the default plus Responses on the same Base URL. Probes without a key returned HTTP 200 from both paths, a bogus `Authorization: Bearer` header is ignored, and `POST /v1/messages` returns 404, so no Anthropic Messages endpoint is exposed.

There is no key or signup, so the template uses the `none` auth requirement like the local `ollama`, `lm-studio`, and `vllm` templates, and its portal is the [landing page](https://index-translate.bilibili.com/) with the `setup` kind. Model discovery uses the OpenAI catalog decoder with the optional credential policy: anonymous `GET /v1/models` returns the OpenAI list shape with one entry, `Index-Translate-35B-A3B` (text and image input, text output, `context_length` 24576, `max_output_tokens` 4096, `function_calling: false`). The README's client script also passes `-m Index-Translate-2B` / `Index-Translate-9B`, and the server's unknown-model error lists further public ids (`index-mt-2b`, `index-mt-9b`, and `-syllable` variants), but none of these appear in `/v1/models`, so no model is hard-coded. The model has no tool calling, so it suits translation workflows rather than agentic coding. Only `index-translate.bilibili.com` is mapped for host inference; `bilibili.com` and `www.bilibili.com` resolve to `custom`. The README publishes no rate limit or service-level terms.

## OrcaRouter — 2026-10-17

`orcarouter` is a gateway Provider for [OrcaRouter](https://www.orcarouter.ai), a multi-provider router whose [llms.txt](https://www.orcarouter.ai/llms.txt) describes it as aggregating OpenAI, Anthropic, Google, and other vendors "behind one OpenAI-compatible API", with provider-prefixed model ids such as `deepseek/deepseek-v4.1-flash` and the `$0` variant `deepseek/deepseek-v4.1-flash-free`. The [Quickstart](https://docs.orcarouter.ai/getting-started/quickstart.md) and [OpenAI SDK guide](https://docs.orcarouter.ai/compatibility/openai-sdk.md) give the Base URL `https://api.orcarouter.ai/v1` and call `POST /v1/chat/completions` with `Authorization: Bearer sk-orca-...`, so Arca uses that Base URL with Chat Completions as the default. [OpenAI-compatible HTTP](https://docs.orcarouter.ai/native-formats/openai-compat.md) documents `POST /v1/responses` on the same Base URL for every chat model. The [Anthropic SDK guide](https://docs.orcarouter.ai/compatibility/anthropic-sdk.md) sets `base_url="https://api.orcarouter.ai"` (the SDK appends `/v1/messages`, and `x-api-key` is accepted), and the [Google GenAI SDK guide](https://docs.orcarouter.ai/compatibility/google-genai-sdk.md) with [Gemini native HTTP](https://docs.orcarouter.ai/native-formats/gemini.md) documents `POST https://api.orcarouter.ai/v1beta/models/{model}:generateContent`; like `unorouter`, Arca stores Anthropic Messages at `https://api.orcarouter.ai` and Gemini at `https://api.orcarouter.ai/v1beta`. Unauthenticated `POST` to `/v1/chat/completions`, `/v1/responses`, and `/v1/messages` returns HTTP 401 (`Invalid API key`, type `orcarouter_api_error`).

Model discovery uses the OpenAI catalog decoder with the optional credential policy: [Models](https://docs.orcarouter.ai/getting-started/models.md) documents `GET https://api.orcarouter.ai/v1/models` in the OpenAI list shape (`{object: "list", data: [{id, object, owned_by, supported_endpoint_types}]}`), and [Free Models](https://docs.orcarouter.ai/routing/free-models.md) says the list accepts anonymous callers while a request carrying an invalid key gets a 401; an anonymous probe returned the catalog. Keys (`sk-orca-…`) are issued from the [Dashboard](https://www.orcarouter.ai/console) ([Get an API key](https://docs.orcarouter.ai/getting-started/get-api-key.md)), which is the template portal; the model pages' samples export them as `ORCAROUTER_API_KEY`. Only `api.orcarouter.ai` is mapped for host inference; `www.orcarouter.ai` and `docs.orcarouter.ai` resolve to `custom`. The [offers page](https://www.orcarouter.ai/offers) lists rotating voucher, student, and hackathon credits plus a rotating `-free` model lineup with tiered rate limits, so no free credit or free model is encoded.

## Meta Model API — 2026-10-17

`meta` / `Meta Model API` is an official Provider for Meta's first-party inference API ([docs overview](https://dev.meta.ai/docs/overview)); the id and display name match the provider key and name in Meta's own OpenCode config. The [Quickstart](https://dev.meta.ai/docs/quickstart) gives the Base URL `https://api.meta.ai/v1` for OpenAI-compatible tools, calls `POST https://api.meta.ai/v1/responses` with `Authorization: Bearer $MODEL_API_KEY`, and points Anthropic-format harnesses at `https://api.meta.ai`. [Choosing an API](https://dev.meta.ai/docs/protocols.md) says Responses, Chat Completions, and Messages run the same models with the same bearer auth and price, calls Responses "the recommended default for new work", notes that Chat Completions does not carry reasoning across turns for external keys, and says the Anthropic SDK should use the base host `https://api.meta.ai` (it appends `/v1/messages`). Arca therefore defaults to Responses at `https://api.meta.ai/v1`, with Chat Completions on the same Base URL and Anthropic Messages at `https://api.meta.ai`. Unauthenticated `POST` to `/v1/responses`, `/v1/chat/completions`, and `/v1/messages` and `GET /v1/models` return HTTP 401 (`invalid_api_key` / `authentication_error`).

Keys come from the Model API dashboard at <https://dev.meta.ai/> → API keys ([Authentication](https://dev.meta.ai/docs/authentication.md)); Meta's examples export them as `MODEL_API_KEY`, which no SDK reads automatically. The [pricing page](https://dev.meta.ai/docs/pricing-rate-limits) lists `muse-spark-1.3`, `muse-spark-1.2`, and `muse-spark-1.1` in Standard mode, the discounted Contributor-mode variants `muse-spark-1.3-contributor` and `muse-spark-1.2-contributor` (content may be used to train Meta models), and `muse-wonder-1.0`. Model discovery uses the OpenAI adapter with a required credential: [List models](https://dev.meta.ai/docs/api-reference/models/list-models.md) documents `GET https://api.meta.ai/v1/models`, and its [schema](https://dev.meta.ai/docs/api-reference/models/schemas.md) returns `{object: "list", data: [{id, object: "model", created, owned_by}]}`. Only `api.meta.ai` is mapped for host inference; `meta.ai`, `www.meta.ai`, and `dev.meta.ai` resolve to `custom`. The docs pages checked here do not state a regional restriction or a signup credit, so neither is encoded.

Arca uses that Base URL with Chat Completions as the default, plus Responses on the same Base URL and Anthropic Messages at `https://apihub.agnes-ai.com` (the Anthropic client appends `/v1/messages`). Unauthenticated `POST` to all three paths and `GET /v1/models` return HTTP 401 (`Token not provided`, type `AgnesAI_error`).

The guides document `agnes-3.0-flash` (512K context, 65,536 max output tokens, text and image-URL input) and `agnes-2.5-flash`. Unauthenticated `POST` to all three paths and `GET /v1/models` on `api.agnes-ai.cn` return HTTP 401 (`未提供令牌`). Its root redirects to <https://platform.agnes-ai.cn/>, the template portal. Note that the Chinese-language pages on `wiki.agnes-ai.com/zh-hans` still show the international host; only `wiki.agnes-ai.cn` documents `api.agnes-ai.cn`.
